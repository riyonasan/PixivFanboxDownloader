# 仕様の入口

FANBOXで本人が閲覧できる投稿の画像・添付・本文を取得するChrome拡張の個人用fork。利用方法は既存の [日本語README](../Readme-JA.md) を正本とし、この文書は開発範囲と受入条件を補う。有料投稿の閲覧権限を解除する機能はない。

## 現在の範囲

- 通常のブラウザダウンロード、命名・ファイル種別設定、取得履歴。
- ローカルEagleへの既存`addFromURL`登録と、作者別の新着自動取得・通知。
- 開発中の「ミニPCへ1件保存（実証）」。選択した添付をブラウザで認証付き取得し、同じPCの補助サービスへ転送する。手順・保証・制限は [FANBOX_FILE_PROOF.md](FANBOX_FILE_PROOF.md) を正本とする。

1件保存の上限は64 MiB。通常ファイルとSQLiteをローカルディスクへ保存し、保存受付とEagle登録を区別する。実証操作は既存の自動取得・履歴・通知を変更しない。Eagle停止中にも利用できる設計だが、実FANBOXでの取得はまだ未実証。

## 受入条件と復旧

まず本人が閲覧可能な有料投稿の小さな添付1件について、通常ファイル保存、サイズ・SHA-256、本人による内容確認、ブラウザと補助サービスの再起動後の保持を確認する。その後、削除無効のEagle登録を実証する。永続FIFO、遠隔設定反映、容量停止・再開、常時収集の本移行は後段とし、現在使える機能とは扱わない。

失敗時はUIに理由を表示する。未確定の転送は本人が同じファイルを再選択してやり直せる。保存済みなら同じ受付を返し、原本を増やさない。不一致や欠損は成功扱いせず、原本・記録を保持する。Eagle送信結果が不明な場合の再送・削除は、後段の照合設計に従う。

## 境界

代表的な操作と手動復旧を基本にする。ただし通常ファイルの永続化、重複受付防止、未確認原本の保持は今回合意済みの要件。将来のFIFOや稀な障害への追加自動復旧を先回りして実装しない。

ブラウザのログイン状態を使い、Cookieは補助サービスへ渡さない。原本・履歴・認証情報をGitやNotionへ保存しない。ミニPCの実行環境、現在のブロッカー、未確認事項は [HANDOFF](HANDOFF.md) に記す。
