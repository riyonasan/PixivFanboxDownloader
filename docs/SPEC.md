# 仕様の入口

FANBOXで本人が閲覧できる投稿の画像・添付・本文を取得するChrome拡張の個人用fork。利用方法は既存の [日本語README](../Readme-JA.md) を正本とし、この文書は開発範囲と受入条件を補う。有料投稿の閲覧権限を解除する機能はない。

## 現在の範囲

- 通常のブラウザダウンロード、命名・ファイル種別設定、取得履歴。
- ローカルEagleへの既存`addFromURL`登録と、作者別の新着自動取得・通知。
- 「ミニPCへ1件保存（実証）」。選択した添付をブラウザで認証付き取得し、同じPCの補助サービスへ転送する。手順・保証・制限は [FANBOX_FILE_PROOF.md](FANBOX_FILE_PROOF.md) を正本とする。

- 開発中の専用収集経路と永続Eagle FIFO、明示設定反映、保存と登録の状態表示。仕様・制限は [FANBOX_FIFO.md](FANBOX_FIFO.md) に集約する。

1件保存の上限は64 MiB。通常ファイルとSQLiteをローカルディスクへ保存し、保存受付とEagle登録を区別する。実証操作は既存の自動取得・履歴・通知を変更しない。既存Eagleへ登録せず保存する。Linuxで有料投稿のPNG1件の認証付き取得・内容確認・ブラウザと補助サービスの再起動保持を実証済み。

## 受入条件と復旧

まず本人が閲覧可能な有料投稿の小さな添付1件について、通常ファイル保存、サイズ・SHA-256、本人による内容確認、ブラウザと補助サービスの再起動後の保持を確認する。削除無効のUNC経由Eagle登録1件と、Eagle原本のサイズ・SHA-256照合も実証済み。永続FIFO、遠隔設定反映、容量停止・再開は実装・模擬検証済み。ミニPCへ配備し、認証付き読取接続とメインPC拡張からの設定保存・読み戻しと専用ブラウザへの適用を確認した。通常保存2件とFIFOによる既存原本照合、メインPCスリープ中の保存とEagle停止後の復帰を確認した。本人承認のOS自動ログイン後、本体再起動からGUI・専用ブラウザ・保存サービスの自動起動とデータ保持を確認した。HDMI切替器をメインPC側へ切り替えた状態の仮想画面共有から既存専用ブラウザ・FANBOXログイン保持・キーリング解除画面なしを本人が確認した。汎用RDPファイルから同じChromeへの接続も本人確認済み。自動画面ロックは本人依頼で無効化した。本人承認でログインキーリングを空パスワード化し、再ログイン後の本体再起動から直結操作・再ログインなしのRDP接続、FANBOXログイン保持、本人操作による通常保存の再受付を確認した。手動ロック後の遠隔復帰、自動周期による新規ファイル取得の再開、FIFOからの新規item POST、ログオフ後の常駐、本移行は未確認。

失敗時はUIに理由を表示する。未確定の転送は本人が同じファイルを再選択してやり直せる。保存済みなら同じ受付を返し、原本を増やさない。不一致や欠損は成功扱いせず、原本・記録を保持する。Eagle送信結果が不明な場合は永続マーカーで照合し、自動再POSTしない。確認待ちは未登録を明示確認してから手動再送する。照合済みでも現在は原本を削除しない。

## 境界

代表的な操作と手動復旧を基本にする。ただし通常ファイルの永続化、重複受付防止、未確認原本の保持は今回合意済みの要件。FIFOの送信意図保存・曖昧時の照合・容量停止は合意済みの範囲。さらに稀な障害への追加自動復旧を先回りして実装しない。

ブラウザのログイン状態を使い、Cookieは補助サービスへ渡さない。原本・履歴・認証情報をGitやNotionへ保存しない。ミニPCの実行環境、現在のブロッカー、未確認事項は [HANDOFF](HANDOFF.md) に記す。
