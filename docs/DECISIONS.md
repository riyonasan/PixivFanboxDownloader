# 技術上の決定

## 2026-10-10 — 既存構成へのテンプレート統合

採用。既存README、追跡中の`dist`、Node/webpack、通知用`.env.example`を維持し、不足する技術文書と作業ルールを補う。共有Codex規則は複製しない。テンプレートのためのサービス・CI・設定システムは追加しない。出典は [DEV_WORKFLOW](../DEV_WORKFLOW.md) に記載。

## 2026-10-10 — 保存実証を通常取得から分離

採用。ブラウザで認証付き取得した添付をFANBOX専用Pythonサービスへ分割転送し、通常ファイルとSQLiteへ保存する。既存Eagle経路・取得履歴を変えずに、永続化と重複受付を先に確かめるため。初期段階は64 MiBまでの手動1件保存とし、FIFO・遠隔設定・自動削除を含めない。保証と制約は [保存実証手順](FANBOX_FILE_PROOF.md) に集約する。

## ブラウザ起動のsandbox対応

採用・適用済み。2026-10-10に利用者が、既存Chrome for Testing一式のroot所有専用コピーと、その実行ファイル1パスに限定したAppArmorの`userns`許可を承認し、ミニPC上で管理者認証して適用した。コピーの一致と所有権、実プロセスへのprofile適用を確認。Chromium自身のsandboxを動かすための例外とし、OS全体の制限は維持する。専用コピーの更新は別途必要。現状と次の操作は [HANDOFF](HANDOFF.md) に置く。

## UNC登録実証の共有と登録先

採用・実証済み。利用者承認後にFANBOX専用の読み取り共有を追加した。共有するのは登録用の通常ファイルのコピーだけで、SQLite・認証・ブラウザ状態・非公開原本領域は含めない。既存のSMBアカウントとメインPCの許可範囲を使い、既存YouTube共有・パスワード・待受・ファイアウォールは変更しない。

最初のPNGはEagleに同一原本が存在したため、既存の名前・連番正規化による重複判定で送信前に停止した。利用者は同じ画像を`FANBOX/UNC登録実証/`以下へ1件だけ登録することを承認した。該当作者の既存形式に合わせ、日付は`YYYY-MM-DD`、連番は3桁とした。実証コピーは本人の手動整理用に残し、既存登録とミニPC原本は保持する。異なる作者や過去の保存形式を一律に改名しない。
