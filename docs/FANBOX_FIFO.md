# FANBOX保存とEagle FIFO

専用ブラウザが本人の閲覧権限でファイルを取得し、同じPCのPython補助サービスへ分割転送する。保存済みの原本からEagleへ順番に登録する。取得用URL・Cookieをサービスへ渡して再取得する経路はない。YouTubeサービスとは別プロセス・別DB・別保存先を使う。

## 利用と現在の制約

小さな有料添付の保存・本人による内容確認・ブラウザ再起動保持と、削除無効のUNC登録・Eagle原本のサイズ／SHA-256照合は実証済み。FIFO版をミニPCへ配置し、メインPC拡張からの設定保存・読み戻し、専用ブラウザへの適用と認証付きEagle読取接続を確認した。通常保存2件、FIFOによる既存Eagle原本の照合、メインPCスリープ中の認証付き保存とEagle停止中の待機・復帰後の照合を確認した。本人承認のOS自動ログインを設定し、本体再起動後のGUI・専用ブラウザ・保存サービスの自動起動とデータ保持を確認した。HDMI切替器をメインPC側へ切り替えた状態の仮想画面共有から、既存専用ブラウザとFANBOXログイン保持、キーリング解除画面なしを本人が確認した。本人承認・操作によるログインキーリングの空パスワード化と再ログイン後、本体再起動から直結操作・再ログインなしのRDP接続、FANBOXログイン保持、本人操作による通常保存の再受付成功を確認した。自動周期による新規投稿の取得とFIFOからの新規item POST 1件を実証した。新規項目は送信意図あり・試行1回でdoneとなり、ミニPC原本・共有コピー・Eagle原本のサイズとSHA-256が一致した。本人が自動取得であることとEagle上の内容の一致・正常表示を確認した。 取得・保存・Eagle登録の通常運用は実証済み。自動削除は未実装・無効。明示ログオフ後の収集継続は保証しない。

メインPCでは接続設定に補助サービスのTailnet IPv4とポート18096を指定し、その接続先だけの拡張権限を許可する。APIトークンは一般設定exportに含めない。投稿ページの「ミニPCへ反映」は作者別条件と取得・命名設定だけを送り、補助サービスから読み戻して一致を確認する。「状態を確認」では設定の専用ブラウザ反映状況、空き容量、保存受付とEagle登録を別々に表示する。

専用ブラウザは非公開の`spool-proof-local.json`で`role: "collector"`を設定した環境だけを新しい収集経路の対象とする。メインPCを`role: "manager"`にすると、設定・状態確認を残して自動スキャンと記事開始を停止する。指定しない通常環境は従来の動作を保つ。同じ非公開ファイルの`remoteURL`で管理接続先を初期設定できるが、拡張の接続設定で指定した値を優先する。専用環境では通常設定の「Eagleに保存」はオフで使う。Eagleへの登録は補助サービスのFIFOが担当する。接続設定の収集チェックは初期状態でオフ。本移行のバックアップと旧側停止後に有効にする。有効化の保存だけでは即時の開始要求を送らない。設定は起動時または既存の自動チェック周期で適用されるため、直後には反映待ちと表示される場合がある。配布ファイルを更新した専用拡張は、ブラウザ再起動だけで新しいworkerコードが使われたと判断せず、拡張の再読み込みと状態表示で確認する。既存作者の取得済み位置と保留・実行中記事、履歴、FIFO、完了履歴を設定で上書きしない。新しく追加した作者は追加時点以後を対象とする。旧側の取得済み位置の移行は、切替時の非公開バックアップから別途行う。

名前は既存`FileName.ts`で取得時に生成し、受付時に固定する。既存の`FANBOX/...`階層と末尾連番のゼロ埋めを無視する重複判定を保つ。過去の作者ごとの名前を一括変更しない。通常ダウンロードと既存Eagleへの直接登録は、補助サービスを使わない設定では従来どおり。

遠隔操作は既存ローカルセッションを共有するDesktop Sharing（3390）で実証済み。screen-share-modeはextendを使い、RDP用の仮想画面を作る。HDMI切替器をメインPC側へ切り替えたまま、同じ専用ChromeとFANBOXログイン保持を本人が確認済み。本人指定の汎用RDPファイルも共有ポート・共有ユーザー名へ合わせ、同じChromeへ接続できたことを本人が確認した。自動画面ロックは本人依頼で無効化した。再起動直後の接続とFANBOXログイン保持は確認済み。手動ロック後の遠隔復帰は未確認。Remote Login（3389）のForce Stopやログオフは専用ブラウザのセッションを終了するため避ける。再起動後の資格情報取得のため、ログインキーリングは全秘密の保存時暗号化を失うことを本人が了承して空パスワード化した。変更前は非公開バックアップへ保持する。OS・RDPのパスワード、PAM・Chromeの保存方式は変更していない。画面休止中のRDP接続拒否と、本人による画面復帰後の接続成功を確認したため、自動画面休止（idle-delay）を300秒から0へ変更した。元値は非公開バックアップ済み。変更後の待機を経たRDP再接続成功を本人が確認した。

## 永続化と復旧

投稿ID＋種別付きファイルIDを受付キーとする。一時ファイルのサイズ・SHA-256、ファイル同期、通常ファイルへの確定、SQLite記録、FIFO受付が完了してから保存成功を返す。同じ受付を繰り返しても原本とキューを増やさない。転送中断時は同じファイルの受付からやり直す。ブラウザ生成本文は投稿と形式に基づく固定IDを使う。

| Eagle状態 | 動作 |
|---|---|
| `pending` | 保存済み、未送信 |
| `retry` | item POST前の接続・共有不在。先頭が待つ間は後続も待つ |
| `submitting` | 送信意図・登録マーカーをPOST前にSQLiteへ保存済み |
| `checking` | マーカー検索とEagle原本のサイズ・SHA-256を照合。自動再POSTしない |
| `done` | メタデータ・サイズ・SHA-256の一致を確認済み |
| `held` | 成否不明、曖昧な重複、照合不一致、個別の恒久エラー。原本を保持して後続を進める |

通常の接続待ちは30秒間隔。送信意図がある項目は、再起動後も照合だけを行う。照合開始から5分で確定できなければ`held`になる。Eagleを長時間停止していた場合も、送信意図のある未確定項目は確認待ちになることがある。確認待ちは状態一覧でEagle側を確認し、未登録と明示確認した場合だけ再送できる。以前の送信意図は消さず試行記録へ保持する。

空き10 GiB未満で新規受付を止め、停止状態はSQLiteへ保存する。20 GiB以上で再開し、中間容量や再起動では再開しない。登録待ちの処理は続ける。サイズが既知のファイルは必要容量も事前確認する。容量と確認待ちの通知は状態変化時に送る。ブラウザ側はファイル取得時の401/403・画像以外の応答を認証／権限確認として扱い、状態変化時に通知する。取得対象がない間の認証維持を保証するものではない。

ストリーム転送の受付上限は1 TiB、1回の取得は30分。1件保存実証UIは64 MiBに制限する。大容量ファイルの実機確認はまだ行っていない。本文HTMLは既存のEagle用生成方法を使う。Eagle原本照合には専用の読み取り共有が必要で、ライブラリが変わった場合は確認待ちにする。

**自動削除は実装・有効化していない。** `done`でもミニPC原本とUNC登録用コピーを保持する。SMB再接続カウンター増加と復帰後の読取、Eagle起動後の既存原本照合、スリープ中の保存と本人の内容確認は成立した。次は照合済み原本だけの自動削除を実装・検証する。

## APIと起動

`python services/spool_proof/runtime.py --local-config services/spool_proof/secrets/runtime.json`で起動する。このJSONはGit除外の専用`secrets/`内へ置く。Linuxのプロセスロックで同じ保存先の二重起動を防ぐ。HTTP受付とFIFO処理は別のSQLite接続を使う。同一プロジェクトの従来`service.py`は手動保存実証用として残す。

非公開JSONの必要項目は`dataDir`、`spoolDir`、`tokenFile`、`extensionId`、`eagleApi`（`/api`まで）、`eagleTokenFile`、`uncRoot`、`eagleLibraryPath`、`eagleLibraryMount`。遠隔管理には`managementBind`と`managementPeer`、通知には`notificationURL`を指定する。値は承認済みの端末設定を使い、Gitへ保存しない。管理待受はミニPCのTailnet IPだけ、接続元はメインPCのTailnet IPだけに限定する。OSの共有・ファイアウォール変更はこの設定ファイルから行わない。

全APIにBearerトークンが必要。WebページのOriginは拒否する。ローカル受付は専用拡張ID、遠隔管理はメインPCの接続元と拡張Originを確認する。任意パスの読取・削除APIはない。

| API | 用途 |
|---|---|
| `GET /v1/health` | 稼働と容量停止状態 |
| `POST /v1/uploads`、`PUT /v1/uploads/{id}`、`POST /v1/uploads/{id}/commit` | ミニPCのloopback限定のファイル受付 |
| `POST /v1/config`、`GET /v1/config` | 許可した設定だけの反映と読取 |
| `POST /v1/config/applied` | ミニPCのloopback限定、専用ブラウザの設定反映確認 |
| `GET /v1/status` | 件数と最近200件の受付・登録状態。SQLiteの履歴自体は保持 |
| `POST /v1/held/{receipt}/resubmit` | `confirmNotRegistered: true`を伴う確認待ちの明示再送 |
