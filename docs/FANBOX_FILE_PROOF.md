# ミニPCへの1件保存実証（Phase 1）

FANBOXのログイン状態で添付画像・ファイルを1件取得し、同じPCの補助サービスへ通常ファイルとして保存するための最小実証です。上限は64 MiB、転送は1 MiB単位です。APIトークン以外の認証情報や取得URLを補助サービスへ渡しません。Python 3.11以上の標準ライブラリだけで動きます。

**2026-10-10にLinux上で、有料投稿のPNG1件の認証付き取得・通常ファイル保存・本人による内容確認・ブラウザと補助サービスの再起動保持を実証しました。** 同じ画像の再受付で同一の受付・サイズ・ハッシュを返し、原本1件を維持しています。本人承認のOS自動ログインによる本体再起動後のGUI・専用ブラウザ・保存サービスの起動は確認済みですが、認証付き取得の無人再開と常時収集は未実証です。再開情報は [HANDOFF](HANDOFF.md) に集約します。この段階では本番の自動収集を切り替えません。UNC経由のEagle登録1件も、別の実証用フォルダで削除無効・原本照合まで確認済みです。この保存ボタンは引き続きEagleへ登録しません。FIFOと遠隔設定反映は [別の専用経路](FANBOX_FIFO.md) として実装し、通常保存・既存Eagle原本照合・メインPCスリープ中の保存と復帰後の照合まで確認しています。FIFOからの新規item POSTと、認証付き取得の無人再開・ログオフ後の常駐は未確認です。実機はFIFO版へ更新済みですが、初期の保存・UNC実証と新経路の実機検証を区別します。自動削除は未実装です。

## 操作

1. 別作業の終了後、ミニPCの空き容量・ポート18096・既存サービスを確認します。FANBOX専用のプロファイルと保存先を使い、既存ブラウザやYouTubeサービスを共有・変更しません。Chromiumの起動・再起動は今回承認された専用環境だけが対象です。
2. このブランチの拡張をビルドして専用Chromiumへ読み込みます。利用者自身がFANBOXへログインします。メインPCからCookieや通常プロファイルをコピーしません。
3. 拡張の「接続設定」を開き、表示された拡張機能IDを控えます。下記でランダムトークンを非公開ファイルへ直接保存し、補助サービスを起動します。保存先はミニPCのローカルディスクです。新しい共有やシステム設定はこの段階では不要です。

```bash
mkdir -p services/spool_proof/secrets
chmod 700 services/spool_proof/secrets
python3 -c 'import secrets; from pathlib import Path; p=Path("services/spool_proof/secrets/api-token.txt"); p.touch(mode=0o600, exist_ok=False); p.write_text(secrets.token_urlsafe(32))'
python3 services/spool_proof/service.py \
  --data-dir services/spool_proof/data \
  --token-file services/spool_proof/secrets/api-token.txt \
  --extension-id YOUR_EXTENSION_ID
```

4. 同じAPIトークンを拡張の接続設定へ入力します。トークンは専用の`chrome.storage.local`キーに保存し、通常設定のエクスポートには含めません。値をチャットや通常ログへ貼り付けないでください。ミニPCへの配置時は、同じPC内で`dist/spool-proof-local.json`にトークンを非公開で配置することで手入力を省けます。保存実証の初回操作時に読み込みます。このファイルはGit・配布ZIP・web_accessible_resourcesに含めません。既に手入力した設定は上書きしません。
5. 閲覧可能な投稿を開き、拡張の設定パネルで「ミニPCへ1件保存（実証）」を開きます。「この投稿の添付ファイルを読む」から小さなファイルを1件選び、保存します。通常の一括ダウンロードは開始しません。
6. 「ミニPCへ保存済み / Eagle未登録」、バイト数、SHA-256、受付IDを確認します。`data/objects/<受付ID>.bin`が原本です。元のファイル名はSQLiteに記録します。画像・articleの添付・file形式が対象で、生成した本文、表紙、外部サービスの動画などはこの実証の対象外です。
7. 利用者が内容を確認します。ブラウザと補助サービスを再起動して同じファイルを選び、同じ受付ID・サイズ・ハッシュが返ること、原本と記録が保持されることを確認します。補助サービス側はファイルを再照合し、保存済みならFANBOXから再取得しません。

## 保存の保証と制限

- 補助サービスは`127.0.0.1:18096`だけで待ち受け、Bearerトークンと拡張機能Originを確認します。LAN/Tailnetからのファイル受付、任意パス操作、Cookie受付、URLからの取得機能はありません。
- 投稿IDと種別付きファイルIDで識別します。ディスク上の名前はIDのSHA-256で生成し、投稿のファイル名をパスとして使いません。
- サイズはFANBOXが返した値と照合します。サイズ不明の画像でも64 MiBを超えません。空き10 GiBと判明している必要サイズを取得前に確認し、各チャンク保存時も空きを確認します。
- 投稿APIは既存経路と同じく`body.post`と直接`body`の両形式に対応します。添付画像は`image/*`の応答だけを受け付け、HTMLなどの応答を保存成功にはしません。
- 一時ファイルをfsyncし、サイズ・SHA-256と確定意図をSQLiteへ保存してから通常ファイルへ確定します。再起動時は確定途中の原本を照合して復旧します。サイズやハッシュが違う原本は保持してエラーにし、保存済み応答を返しません。
- 中断した未確定ファイルは残します。同じファイルを明示的に再実行すると、未完了の一時ファイルを先頭から再転送します。保存済みの原本は上書きしません。同じIDで名前や期待サイズが変わった場合も自動上書きしません。
- この実証の操作は、自動取得カーソル、閲覧制限記事の保留、IndexedDBの通常ダウンロード履歴・Eagle履歴、通知を変更しません。既存の自動取得は従来どおりEagle待ちになる場合があります。Eagle非依存なのは今回の1件保存経路です。
- SQLiteと原本を一緒に保持してください。完了原本・中断原本の自動削除はありません。常駐設定・再起動時の自動起動はLinux実証時に環境を確認して準備し、ブラウザを置いただけで常駐実証済みとは扱いません。

## ローカル検証

```text
python -B -m unittest discover -s services/spool_proof -p test_service.py -v
node --test tests/spool-proof.cjs
```

保存・HTTP受付テストと、模擬ブラウザの認証付きストリーミング取得テストを分離しています。テストは実FANBOX・Eagle・ntfyへ接続しません。実アカウントでの1件取得・本人の内容確認は上記の実機実証で確認済みですが、スリープ中の保存と復帰後の既存Eagle原本照合はFIFO版で確認済みです。本体再起動後の自動起動とデータ保持は確認済みですが、認証付き取得の無人再開・常時収集は別途実証が必要です。
