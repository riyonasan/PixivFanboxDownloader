## 確認済みの根拠

- Linuxの専用Chromiumで本人が有料投稿のPNG1件を保存。通常ファイル・SQLite・UI・読み戻しコピーのサイズ・SHA-256が一致し、本人が内容の一致と正常表示を確認した。ブラウザと補助サービス再起動後もログイン・同じ受付・原本1件を保持した。
- 本人承認後に専用の読み取りSMB共有を追加。登録用PNGコピーをUNCから読み、サイズ・SHA-256一致と通常ユーザーの書き込み拒否を確認。既存YouTube共有も引き続き読める。
- 既存Eagleに同じPNGが存在することをサイズ・ハッシュ・投稿URLまで照合した。連番`1`と`001`を同じと扱う既存重複判定で、通常の登録先へのitem POSTは行わなかった。
- 本人承認の`FANBOX/UNC登録実証/`以下へ`addFromPath`を1回送信。受付直後は一覧へ未反映だったが、item POSTを繰り返さずマーカー照合のみで確定した。Windows上とミニPCの読み取り専用CIFS経由のEagle原本が、ミニPC原本・UNCコピーとサイズ・SHA-256まで一致した。原本と実証コピーは保持、削除処理はない。
- 1件実証では既存`Eagle.ts`の階層・命名・重複判定を直接再利用した。item POST前の排他的・fsync付き意図記録を使い、記録があれば照合のみ行う。必要なfolder/createはitem意図保存より前に発生する。これはFIFOやミニPCからの自動送信の実装ではない。
- FIFO版のブラウザ模擬43件（管理専用モード・PNG添付の識別を含む）、Linux Python36件（HTTP2件を含む）、既存自動取得13件、分離出力のwebpackが成功。送信前クラッシュ、受理後の応答喪失、DB更新失敗、不一致、重複受付、中断・再起動、設定失敗、10/20 GiBを模擬確認した。既存自動取得テストは未追跡ファイルを変更せず、新依存だけを外部fixtureでstub化した。
- WindowsのHTTP模擬試験では接続リセットが再現し、原因は未確定。独立の原因・方針レビューに従って仮のbody drain修正を除去し、同一候補を対象OSのLinuxでHTTP単独・全体とも確認した。Windows版サービスの動作保証とは扱わない。共有設定の実機testparm検証とUNC証拠は保持している。

SSH・端末固有パス・接続先は承認済みローカル設定を使う。利用者ホーム内の`services/fanbox-file-proof`が専用配置で、`dist/`、`browser-profile/`、`services/spool_proof/data/`と`secrets/`を使う。共有は登録用コピーだけを置く専用領域。秘密値、実ファイル名・ID・画像・ハッシュ・ローカル実証スクリプトは公開Gitへ入れない。

Ubuntu 26.04.1、Python 3.14.4、Chrome for Testing 151。配置時空き約387 GiB。専用Chromiumコピーと実行パス限定のAppArmor profileは本人承認後に適用し、全303ファイル・所有権・実プロセス適用を確認。OS全体のuser namespace制限は有効。専用ブラウザ一式の更新は別途必要。

従来のtransient unitは停止し、永続user unitの`fanbox-storage.service`と`fanbox-browser.service`へ切り替えた。保存サービスはloopbackと指定Tailnet IPの`18096`、ブラウザは従来の専用プロファイルを使う。本体再起動後の自動起動、遠隔セッション終了時の常駐、大容量ファイル、認証切れ・容量復旧、メインPCスリープ中の取得は未実証。画面セッション切替でブラウザが終了した事実があり、常時収集の成立とは扱わない。

EagleのUNC実証はメインPCのローカルAPIから行った。FIFO版の配備後、ミニPCから認証付きEagle読取APIと読み取り専用CIFSライブラリへ接続できることを確認した。メインPCからTailnet経由の状態APIも読める。既存YouTubeサービスは変更していない。

メインPCのChromeを本人が終了した後、FANBOX拡張設定・FANBOX IndexedDBをアクセス制限した非公開領域へバックアップし、ハッシュ照合した。ミニPCでも専用ブラウザ・保存サービスを停止して、プロファイル・DB・通常ファイル・登録用コピーを非公開バックアップした。メインPCの拡張設定とFANBOX履歴だけをミニPCへコピーし、Cookieは転送していない。

メインPCは非公開設定の`role: manager`にし、Chrome再起動後も自動スキャンと記事開始を止める。本人の個別承認後に生成済みJS4ファイルを最新ビルドへ更新し、元の4ファイルは非公開バックアップへ保持した。拡張UIから設定の反映・読み戻しが成功し、サービスに作者31件と取得設定45項目の永続保存を確認。本人が専用ブラウザの収集チェックを保存し、再起動後のFANBOX表示・ログイン保持を確認した。再読み込み前は状態確認が無応答で、旧workerコードのキャッシュ残存も確認した。本人による当該拡張の明示再読み込み後、サービス側で専用ブラウザの設定反映完了を確認した。FIFOはまだ増えていない。自動チェックの一部成功後に非同期応答の接続断が記録された。本人が自動チェック用と考えられるクエリ付きタブを操作したが、操作対象との厳密な対応は未確認。さらに本人が通常設定の「Eagleに保存」をオンにしたと確認でき、記録上も適用後にそのフラグだけが変わっていた。設定競合の修正は追加せず、オフへ戻して当該拡張を再読み込みし、自動タブを操作しない確認を依頼中。キャッシュや履歴は削除していない。

user unitは有効だが、現時点ではuser lingeringとGDM自動ログインは無効。専用ブラウザはgraphical-session.targetに従い、GUIログイン前の起動や遠隔セッション終了時の継続は保証していない。OS再起動の受入試験で確認し、追加のログイン・権限変更が必要なら具体案を示す。
