# 概要

これは、Pixiv Fanbox上のファイルを一括ダウンロードするためのChromeブラウザ拡張機能です。

ファイルタイプのフィルタリング、ファイル名のカスタマイズ、複数の言語に対応しています。

**注意：** このプログラムはFanbox上の有料コンテンツを直接解除することはできません。有料コンテンツをダウンロードするには、まず購入する必要があります。

# 使用方法

## このフォークのEagle連携

Eagleを起動して登録先のライブラリを開き、設定画面の「ファイルタイプ」の上にある「Eagleに登録」にチェックを入れると、通常ダウンロードの代わりにEagleへ送信します。チェックを外すと通常ダウンロードに戻ります。

- 対象のファイルタイプと命名設定は既存の設定を使用します。Eagleの `FANBOX` 配下に命名設定の階層を作り、既存の同名フォルダを再利用します。
- アイテムのURLには元のFANBOX記事URLを設定します。タグ・メモは追加しません。
- FANBOX上のファイルは、拡張機能がブラウザのログイン状態を使って取得し、データをローカルEagleへ送信します。通常のダウンロードフォルダには保存せず、認証CookieをEagleに渡す必要もありません。ファイルを一時的にメモリに展開するため、大容量ファイルを扱うときは同時処理数を抑えてください。
- Eagleへの送信受付と取り込み完了は異なります。取り込み結果はEagleで確認してください。
- 「重複するファイルをダウンロードしない」をオンにすると、Eagle登録でも拡張機能のIndexedDB履歴にある同じ記事・ファイルをスキップします。履歴にないファイルはEagleの記事フォルダ内で名前と拡張子を照合し、既存の項目が見つかれば履歴に記録してスキップします。連番のゼロ埋めだけが異なる名前も同じ項目として扱い、以後は履歴だけで判定します。通常ダウンロードの履歴とは区別されます。それ以外で名前やフォルダ構成を変更した項目は照合できず、ファイルの中身までは比較しません。Eagleへの登録依頼を受け付けた時点で履歴に残すため、Eagle側で後から取り込みに失敗した場合は、この設定を一時的にオフにして再登録してください。
- HTML本文内の画像・添付リンクは元のURLを参照するため、閲覧にはネット接続やFANBOXへのアクセス権が必要です。

この機能はローカルのEagle API（`http://localhost:41595`）を使用します。Chrome Webストア版には含まれないため、このフォークの `dist` フォルダを「パッケージ化されていない拡張機能」として読み込んでください。

## 新着の自動取得

FANBOXの「フォロー中のクリエイター」または「支援中のクリエイター」ページで拡張機能の「自動取得の管理」を開き、対象のクリエイターと価格条件を保存できます。無料・有料の選択に加え、有料投稿の下限・上限を指定できます。どちらのページで保存しても登録内容は共通で、既存の手動クロール設定には影響しません。

有料は支援中、または今後支援する予定のクリエイターだけオンにしてください。新規登録時の有料チェックはオフです。加入する予定のない上位プランの記事を取得対象に含めないよう、必要に応じて価格上限も設定してください。

登録した時点より後に公開された投稿を、Chrome起動時と起動中の約1時間ごとに確認します。Chromeを閉じていた間の新着も次回起動時に確認します。自動取得は現在のファイルタイプ、命名、Eagle登録の設定を使います。確認時にはFANBOXのタブを非アクティブで一時的に開き、投稿の処理時にも対象投稿のタブを非アクティブで開きます。どちらも処理後に閉じます。Eagle登録を選んでいる場合、Eagleを起動してライブラリを開くまで未処理の投稿を保持します。失敗した投稿は約1時間後に再試行します。

本文が閲覧制限されている有料記事は、失敗通知を送らず「保留」としてブラウザ内に保存します。他の新着の取得は続行し、保留記事は前回の閲覧制限確認から24時間以上経過した定期確認で再試行します。Chromeを閉じていた場合は次回起動時以降に確認します。再加入して閲覧可能になれば通常どおり取得し、成功後に保留から削除します。通信エラーなど、閲覧制限以外の失敗は従来どおり約1時間後の再試行と失敗通知の対象です。

「自動取得の管理」には保留件数と、クリエイターごとの「保留記事を再確認」ボタンが表示されます。再加入直後に押すと24時間を待たずに再確認できます。設定を編集した場合は先に保存してください。再確認は保存済みの無料・有料と価格条件に従い、ほかの記事の処理中やEagleの起動待ちの場合は順次処理します。有料をオフにする、価格範囲を狭める、登録を解除するなどして対象外になった未処理・保留記事は、設定の保存時に対象から外れます。すでに処理中の記事は中断しません。

登録前の過去投稿や、この保留機能を導入する前に閲覧制限でスルーされた投稿は自動取得しません。必要な場合は従来の手動クロールで対象期間を指定し、「重複するファイルをダウンロードしない」を有効にして回収してください。有料を後からオンにした場合も、すでに新着確認を終えた期間にはさかのぼりません。

### ntfy通知

リポジトリ直下の `.env.example` を参考に、Git管理外の `.env` に `NTFY_URL=https://ntfy.sh/自分のトピック` を設定して `npm run ts` を実行してください。ビルド時に `dist/ntfy-config.json` が生成されます。Chromeで拡張機能を再読み込みすると、自動取得した投稿の処理完了・失敗をntfyへ通知します。成功通知の本文はクリエイター表示名、記事名、記事URLの3行です。定期確認だけでは通知せず、通常の手動ダウンロードも通知対象外です。有料投稿の本文が閲覧制限で取得できない場合は保留し、その時点では通知しません。

`.env` と生成された設定ファイルはGit管理外ですが、生成した拡張機能の中には送信先が含まれます。また、ntfy.shのトピックは公開です。トピックを知る人は通知を閲覧・投稿できるため、拡張機能の配布物を公開しないでください。

## 通常ダウンロード

- この拡張機能をインストールした後、fanboxページを更新すると、ページの右側に青いダウンロードボタンが表示されます。このボタンをクリックして使用を開始してください。
- ダウンロードしたファイルはブラウザのダウンロードディレクトリに保存されます。別の場所に保存したい場合は、ブラウザのダウンロードディレクトリを変更する必要があります。
- ダウンロード時に「各ファイルの保存場所を尋ねる」ブラウザ設定をオフにしてください。そうしないと、保存先を尋ねるダイアログが表示されます。
- ダウンロードしたファイル名に異常がある場合、ダウンロード機能を持つ他のブラウザ拡張機能を無効にしてください。
